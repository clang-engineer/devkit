# Reference authoring instructions

- **Before creating, editing, moving, or reviewing any file in `cheatsheets/`, read `CHEATSHEET_GUIDELINES.md` in full.** It is the single source of truth for cheatsheet writing; do not duplicate or replace its rules here.
- Read the entire target cheatsheet before changing it. Check its existing operating model, ASCII diagrams, feature coverage, command patterns, and links. Choose between editing the cheatsheet, linking a reference, or placing deeper discussion in a blog post based on the guidelines.
- After editing, recheck the whole document against the guidelines' **완료 전 검증** section. Distinguish a partial edit from a full-document review in the report.
- For `catalog.json` changes, read `README.md`, validate category tags and references against the viewer schema, and run the applicable catalog preparation/tests. The blog consumes the catalog directly, so schema compatibility matters.
- Keep official specifications in official references, deeper explanations and incidents in the blog, and personal configuration in dotfiles, as specified in the guidelines.
