# Cheatsheet 작성 원칙

> **짧게 설명하고, 구조로 이해시키고, 패턴으로 기억하게 한다.**

Devkit 치트시트는 공식 문서의 축약본이 아니다. 명령어의 **문법·대상·상태 변화·반복 패턴**을 압축해 보여 주어, 처음 보는 명령도 유추할 수 있게 돕는다.

## 작성 기준

1. **대상부터**: 명령이 조작하는 대상과 계층을 작은 ASCII 그림 또는 한 줄로 보여 준다. 불필요하면 생략한다.
2. **문법과 약어**: `command [options] target`의 각 요소를 풀되, 자명한 표현은 설명하지 않는다. 공식 약어와 암기를 위한 연상은 구분한다.
3. **패턴으로 묶기**: create/list/select/delete 등 공통 동사와 대상별 명령을 묶는다. 예외는 바로 옆에 적는다.
4. **동작을 보여 주기**: 명령 실행 전후에 무엇이 바뀌는지 예제 하나로 설명한다. 명령어 표를 중복하지 않는다.
5. **공식 문서로 연결**: 전체 옵션·버전별 차이·드문 기능은 공식 문서를 가리킨다. 확인하지 않은 옵션 의미를 추측하지 않는다.

## 분량과 편집

- **한눈에 이해되는 최소 분량**을 우선한다. 문단보다 짧은 표·ASCII·주석 달린 예제를 쓴다.
- 같은 명령을 '핵심', '30초', '전체 목록'에서 반복하지 않는다.
- 한 번 배운 규칙으로 여러 명령을 추론할 수 있는 설명만 추가한다.
- 단순 명령 나열, 설치 안내 복제, 장황한 내부 원리 설명은 피한다.
- 도구마다 구조가 다르므로 형식을 강제하지 않는다. CLI는 문법, 설정 도구는 적용 순서, TUI는 조작 계층을 중심으로 정리한다.

## 경계

- **Devkit**: 명령어를 이해하고 추론하는 압축 레퍼런스 및 도구 관계.
- **Blog**: 내부 원리와 심화 학습.
- **dotfiles**: 실제 개인 설정과 재현.
- **공식 문서**: 전체 명세와 최신 동작.

## 검토 질문

> 이 문서를 읽고 명령어를 통째로 외우지 않아도, 비슷한 명령을 보고 의미와 동작을 추론할 수 있는가?

그렇지 않다면 더 길게 쓰기보다 **구조를 다시 잡거나, 공식 문서 링크만 남긴다.**
