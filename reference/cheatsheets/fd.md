# fd — 파일·디렉터리 탐색 치트시트

> `fd`는 **파일 이름·경로 조건으로 후보를 생성하는 도구**다. 파일 내용 검색은 `rg`, 후보의 대화형 선택은 `fzf`가 담당한다.

## 전체 작동 모델

```text
검색 시작 위치(PATH)
        │
        ▼
디렉터리 순회 ── ignore / hidden 규칙
        │
        ▼
이름 패턴 + 파일 유형 + 확장자 + 깊이
        │
        ▼
일치한 파일·디렉터리 경로 출력
        │
        ├─ 화면에서 확인
        └─ 파이프 → fzf 등 다른 도구
```

`fd`는 기본적으로 파일 **내용이 아닌 이름과 경로**를 검색한다. 기본 검색어는 정규식이며, 기본 검색 위치는 현재 디렉터리다.

## 1. 명령을 읽는 법

```text
fd [OPTIONS] [PATTERN] [PATH]
      │          │       └─ 어디서 탐색할까?
      │          └─ 이름·경로에 어떤 패턴을 찾을까?
      └─ 대상 유형·깊이·제외 규칙 등을 어떻게 적용할까?
```

```sh
fd 'config'                   # 이름에 config가 포함된 경로
fd 'service' src/             # src 아래에서 검색
fd -e java                    # Java 확장자 파일
fd -t f                       # 파일만
fd -t d                       # 디렉터리만
```

## 2. 탐색 범위와 조건

| 목적 | 옵션 | 예 |
|---|---|---|
| 파일만 | `-t f` | `fd -t f` |
| 디렉터리만 | `-t d` | `fd -t d` |
| 확장자 | `-e` | `fd -e log` |
| 최대 탐색 깊이 | `-d` | `fd -d 2` |
| 경로 제외 | `-E` | `fd -E node_modules` |
| Glob 패턴 | `-g` | `fd -g '*.yml'` |
| 리터럴 문자열 | `-F` | `fd -F 'a.b'` |

기본적으로 숨김 파일과 ignore 규칙에 걸리는 경로는 제외한다.

```sh
fd -H 'config'          # 숨김 파일 포함
fd -I 'config'          # ignore 규칙 무시
fd -HI 'config'         # 둘 다 적용
```

`-H`와 `-I`는 다른 제한을 해제한다. 결과가 없을 때는 검색어를 바꾸기 전에 이 차이를 확인한다.

## 3. 결과를 어떻게 활용할까

```sh
fd -e log logs/                 # 로그 파일 목록
fd -t f -e yml                  # YAML 파일 목록
fd -t f | fzf                   # 목록에서 대화형 선택
```

`fd`는 후보 경로를 stdout으로 출력하므로 다른 명령에 연결할 수 있다. 다만 파일 이름에 공백·줄바꿈이 있거나 여러 파일을 실행 인자로 넘길 때는 구분 방식에 주의한다. `fd -0`는 NUL 구분 출력을 지원한다.

## 4. find·rg·fzf와의 관계

| 도구 | 주 역할 |
|---|---|
| `find` | 파일 메타데이터·조건식·작업 실행까지 폭넓게 지원 |
| `fd` | 사람이 쓰기 편한 이름·경로 중심 탐색 |
| `rg` | 파일 **내용** 검색 (`--files`로 경로 나열도 가능) |
| `fzf` | 이미 생성된 후보를 대화형으로 선택 |

`fd`가 `find`를 완전히 대체하지는 않는다. 복잡한 조건식과 파일 메타데이터 중심 작업에는 `find`가 더 적합할 수 있다. 반대로 일상적인 파일·디렉터리 탐색에는 `fd`의 간결한 옵션이 유용하다.
