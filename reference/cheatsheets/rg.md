# ripgrep (rg) — 검색 범위와 출력 구조

> `rg`는 **검색 대상 파일 선택 → 패턴 매칭 → 결과 출력**의 세 단계로 이해한다. 파일 탐색(`fd`)이나 결과 선택(`fzf`)과 역할을 구분한다.

## 전체 작동 모델 — 파일 선택에서 결과 출력까지

```text
검색 경로(PATH) ── ignore / hidden / binary ── glob(-g) / type(-t)
                                                     │
                                                     ▼
                                                검색 대상 파일
                                                     │
                                            PATTERN 매칭
                                                     │
                                   ┌─────────────────┼────────────────┐
                                   ▼                 ▼                ▼
                               일치한 줄          파일 목록        주변 문맥
                               -n / -o             -l              -C
                                   └─────────────────┼────────────────┘
                                                     ▼
                                                   출력
                                             │             │
                                         터미널        파이프(stdin)
```

**파일이 검색되지 않으면 패턴보다 먼저 검색 대상에 포함되는지 확인한다.** 반대로 파이프로 들어온 텍스트를 검색할 때는 파일 탐색 단계를 거치지 않는다.

### 명령을 읽는 법

```text
rg [OPTIONS] PATTERN [PATH ...]
       │       │         └─ 어디에서 찾을까?
       │       └─ 무엇을 찾을까? (기본: 정규식)
       └─ 검색 범위·매칭·출력을 어떻게 제어할까?
```

```sh
rg 'TODO' src/             # src 안에서 내용 검색
rg -n 'TODO'               # 일치한 줄 번호 표시
rg -g '*.rs' 'unsafe'      # 경로 glob으로 파일 제한
rg -t py 'import'          # 등록된 파일 유형으로 제한
rg -F 'a.b'                # 정규식이 아닌 문자 그대로 검색
```

## 1. 검색 범위 — 어떤 파일을 읽는가

| 구성 | 의미 | 예 |
|---|---|---|
| `PATH` | 탐색 시작 경로 | `rg TODO src/` |
| `-g` / `--glob` | 경로 패턴으로 포함·제외 | `-g '*.md'`, `-g '!vendor/**'` |
| `-t` / `--type` | 사전 정의된 파일 유형 | `-t py` |
| `--files` | 내용 검색 없이 대상 파일 경로 나열 | `rg --files -g '*.rs'` |

```text
기본: ignore 규칙 준수 + 숨김 파일 제외 + 바이너리 검색 제한
  ├─ -u   : ignore 규칙 무시
  ├─ -uu  : ignore 규칙 무시 + 숨김 파일 포함
  └─ -uuu : 위 제한 완화 + 바이너리 검색 제한 완화
```

`-u`를 반복할수록 검색 범위가 넓어진다. `-uuu`는 방대한 파일을 읽을 수 있으므로 경로를 좁혀 사용한다. 숨김 파일만 포함하려면 `--hidden`을 사용하고, `.git` 등의 제외가 필요하면 glob을 함께 적용한다.

**검색 누락 진단:** `rg --files -g '*.rs'`로 파일이 대상인지 확인한 다음 `rg -n -g '*.rs' 'unsafe'`로 내용을 검색한다.

## 2. 패턴 — 무엇을 일치시킬까

| 옵션 | 의미 | 예 |
|---|---|---|
| 기본 | 정규식 검색 | `rg 'error|warn'` |
| `-F` | 정규식이 아닌 고정 문자열 | `rg -F 'a.b'` |
| `-i` | 대소문자 무시 | `rg -i 'exception'` |
| `-w` | 단어 경계 기준 매칭 | `rg -w 'user'` |

## 3. 출력 — 무엇을 가져올까

| 목적 | 옵션 | 예 |
|---|---|---|
| 일치한 줄과 줄 번호 | `-n` | `rg -n 'TODO'` |
| 일치한 파일 경로만 | `-l` | `rg -l 'TODO'` |
| 일치한 부분만 | `-o` | `rg -o '[0-9]+'` |
| 앞뒤 문맥 | `-C N` | `rg -C 5 'Exception' app.log` |
| 일치한 줄 수(파일별) | `-c` | `rg -c 'ERROR' logs/*.log` |
| 구조화된 결과 | `--json` | `rg --json 'TODO'` |

`-c`는 기본적으로 **매칭 횟수**가 아니라 **매칭된 줄 수**다. `-l`은 내용이 일치한 파일을 찾지만 `--files`는 내용을 검색하지 않는다.

## 4. 입력 — 파일 검색과 파이프 검색

```sh
rg -n 'ERROR' app.log                 # 파일 내용을 직접 읽기
docker logs my-app 2>&1 | rg 'ERROR'  # 다른 명령의 출력을 stdin으로 검색
```

두 번째 경우 `rg`는 파일을 탐색하지 않고 파이프로 전달된 텍스트를 필터링한다. `2>&1`은 표준 오류도 파이프로 합치는 셸 구문이다.

## 5. 실무 패턴 — 로그 확인

```sh
rg -ni 'error|exception|failed' app.log      # 오류 후보
rg -n -C 5 'Exception' app.log               # 오류 전후 문맥
tail -F app.log | rg --line-buffered -i 'error|warn'  # 실시간 필터
```

`-C 5`는 일치한 줄의 앞뒤 5줄을 보여준다. `--line-buffered`는 파이프 출력이 버퍼에 오래 머무르지 않도록 한다. 단, 마지막 예시는 **매칭되지 않은 줄을 버리므로** 오류 전후 맥락을 모두 보려면 원본 로그도 함께 확인한다.

## 6. fd·fzf와의 관계

```text
fd             파일명·경로를 기준으로 후보 생성
rg             파일 내용 검색 (또는 --files로 파일 목록 생성)
fzf            입력받은 후보를 대화형으로 선택

rg -l 'TODO' | fzf      → TODO가 들어 있는 파일 중 선택
rg --files | fzf       → rg의 대상 파일 목록에서 선택
```

`fzf`는 검색 엔진이 아니라 **선택 인터페이스**다. 파일 이름 탐색은 `fd`, 코드 내용 탐색은 `rg`가 자연스럽지만 `rg --files`처럼 역할이 겹치는 기능도 있다. LazyVim의 Live Grep 역시 보통 내부에서 `rg`를 사용하므로, 편집기 안의 검색을 굳이 셸 명령으로 중복할 필요는 없다.
